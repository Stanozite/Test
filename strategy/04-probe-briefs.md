# 04 — Probe Briefs: พิสูจน์ว่ามีคนจ่ายจริง ภายใน 4 สัปดาห์

> **กฎ**: เขียนสมมติฐาน + วิธีวัด + เกณฑ์ฆ่า **ก่อน**เริ่ม · บันทึกผลดิบลง `templates/probe-log.md` แบบ append-only
> **เป้าหมายไม่ใช่ทำให้ probe สำเร็จ — เป้าหมายคือรู้ความจริงให้เร็วที่สุดด้วยเงินน้อยที่สุด**

**งบรวมทั้ง 3 probe: ≤ $500 + 4 สัปดาห์** ถ้าใช้เกินนี้แปลว่ากำลัง build อยู่ ไม่ได้ probe

---

## โครงร่างมาตรฐานของ probe (ใช้ซ้ำได้ทุกอัน)

```
สมมติฐาน:     [ใคร] เจ็บกับ [อะไร] มากพอที่จะ [จ่าย/ให้เวลา] เพื่อแก้
วิธีที่ผิดได้:  ถ้า ___ ไม่เกิดภายใน ___ แสดงว่าสมมติฐานผิด
วัดด้วย:       ตัวเลขเดียว ไม่ใช่ความรู้สึก
เกณฑ์ฆ่า:      เขียนเป็นตัวเลข ห้ามต่อรองหลังเริ่ม
งบ/เวลา:       ___ / ___
```

## PROBE-1 · F1 Outcome Verification — **Money probe** (ให้น้ำหนักสูงสุด)

| | |
|---|---|
| **สมมติฐาน** | บริษัทที่ขาย AI agent แบบ outcome-based (หรือกำลังจะเปลี่ยนไป) เจ็บกับการ "พิสูจน์ว่า outcome นับได้" มากพอจะจ่ายเงินให้บุคคลที่สามตรวจ |
| **สมมติฐานที่ต้องฆ่าให้ได้ก่อน** *(แก้ไข 2026-08-29 ก่อนเริ่ม probe — ดู `probe1-target-list.md` §4)* | ⚠️ **ตลาดกว้างพอจะเป็นบริษัทไหม** — ต้องได้ครบทั้ง 3 ข้อใน 1 สัปดาห์: (ก) **≥40 ราย** (ข) **≥12 รายนอกหมวด customer support** (ค) **≥8 รายที่ยืนยันราคา/หน่วยวัดได้จากหน้าเว็บของบริษัทเอง** ไม่ใช่จากบล็อกเปรียบเทียบ · ขาดข้อใดข้อหนึ่ง = **ฆ่าทันที**<br>เหตุผลที่แก้: ด่านเดิมวัด *ตลาดมีไหม* ซึ่งตอบแล้วว่ามี (~21.7% ของสัญญาซอฟต์แวร์องค์กร Q1 2026 เป็น outcome-based) ความเสี่ยงที่แท้จริงคือ **ถ้าขายได้เฉพาะ CX มันคือ feature ของ CX platform ไม่ใช่บริษัท** |
| **ทำอะไร** | 1) ✅ ลิสต์ผู้สมัคร 47 รายพร้อมแล้วที่ [`probe1-target-list.md`](probe1-target-list.md) — งานที่เหลือคือ**ตรวจชั้น T3 ให้ผ่านเกณฑ์ (ข) และ (ค)** ไม่ใช่หาชื่อเพิ่ม · 2) ยิงอีเมล/DM ส่วนตัว 40 ฉบับ — ไม่ขาย ถามคำถามเดียว: *"ตอนนี้ตัดสินยังไงว่าเคสไหนนับเป็น resolution และเคยมีลูกค้าเถียงไหม"* · 3) คุย 45 นาที · 4) เสนอ paid pilot $2,000 |
| **วัดด้วย** | จำนวน (ก) นัดคุยที่ได้ (ข) รายที่บอกว่า**เคยมีข้อพิพาทจริง** (ค) รายที่ยอมจ่าย pilot |
| **เกณฑ์ผ่าน** | ≥6 นัดคุย · ≥4 ยืนยันว่าเคยเถียงกับลูกค้าเรื่องการนับ · **≥1 จ่ายหรือเซ็น LOI** |
| **เกณฑ์ฆ่า** | ไม่ผ่าน 3 ข้อข้างบน · หรือ <3 นัดคุยใน 2 สัปดาห์ · หรือ 10 คนคุยแล้วไม่มีใครเคยมีข้อพิพาท (= ปัญหายังไม่เกิด) |
| **งบ/เวลา** | $100 (เครื่องมือหาอีเมล) / 2 สัปดาห์ |

> **คำถามที่ต้องได้คำตอบให้ได้ในทุกบทสนทนา**: ผู้ซื้อคือ *คนขาย agent* หรือ *องค์กรที่ซื้อ agent* — สองคำตอบนี้นำไปสู่คนละบริษัท ห้ามจบ probe โดยยังไม่รู้

## PROBE-2 · F2 Self-building Eval — **Build probe**

| | |
|---|---|
| **สมมติฐาน** | ทีมที่รัน agent ใน production ไม่มี eval set เพราะ*ไม่มีเวลาสร้าง* ถ้ามีของที่สร้างให้จาก traces อัตโนมัติ เขาจะใช้ซ้ำ |
| **ทำอะไร** | prototype 72 ชั่วโมง: รับ traces (OTel/LangSmith/ไฟล์ JSON) → คายชุดเทสต์ + รายงาน "ตรงไหนเริ่มเพี้ยน" · เปิดฟรี ปล่อยใน 1 ชุมชนที่ ICP อยู่จริง |
| **วัดด้วย** | **จำนวนคนที่กลับมาใช้รอบที่ 3 โดยไม่ถูกเตือน** (ไม่ใช่ยอดสมัคร ไม่ใช่ star) |
| **เกณฑ์ผ่าน** | ≥5 คนใช้รอบที่ 3 · ≥2 คนถามเองว่า "มีแบบเสียเงินไหม" |
| **เกณฑ์ฆ่า** | สมัคร >50 แต่กลับมารอบ 3 <2 คน = classic vitamin ฆ่าทิ้ง |
| **งบ/เวลา** | $50 (hosting) / 2 สัปดาห์ (72 ชม. build + 1 สัปดาห์สังเกต) |

## PROBE-3 · F3 Ground-Truth Feed — **Demand probe**

| | |
|---|---|
| **สมมติฐาน** | มีโดเมนที่ "ข้อมูลผิด = เสียเงินจริงทันที" และคนในโดเมนนั้นยอมจ่ายรายเดือนเพื่อ feed ที่ถูกและอัปเดต |
| **ทำอะไร** | 1) เลือก 3 โดเมนผู้สมัคร (เช่น พิกัดศุลกากร/ภาษีนำเข้า · กฎ compliance ที่เปลี่ยนบ่อย · มาตรฐานอุตสาหกรรมที่มีค่าปรับ) · 2) ทำ feed ตัวอย่างจริง 1 สัปดาห์ของข้อมูล · 3) landing page 3 หน้า ยิงหา 30 ราย/โดเมน · 4) **ทดสอบเปรียบเทียบ**: ให้ LLM ตอบคำถามในโดเมนนั้นแบบไม่มี feed → นับว่าผิดกี่ % |
| **วัดด้วย** | อัตราผิดของ LLM เปล่า (ยิ่งสูงยิ่งดีสำหรับเรา) + จำนวนคนที่ขอ feed ต่อ |
| **เกณฑ์ผ่าน** | มี ≥1 โดเมนที่ LLM เปล่าผิด **>30%** และมี ≥3 รายขอ feed ต่อเดือนหน้า |
| **เกณฑ์ฆ่า** | ทุกโดเมน LLM เปล่าผิด <15% = โมเดลรู้อยู่แล้ว ไม่มีช่องว่างให้ขาย |
| **งบ/เวลา** | $150 / 2 สัปดาห์ |

## ตารางเวลา 4 สัปดาห์

| สัปดาห์ | PROBE-1 | PROBE-2 | PROBE-3 |
|---|---|---|---|
| 1 | สร้างลิสต์ 40 ราย (**ด่านตายด่านแรก**) | build 72 ชม. | เลือกโดเมน + ทดสอบอัตราผิดของ LLM |
| 2 | ยิง 40 ฉบับ + เริ่มคุย | ปล่อย + สังเกต | ทำ feed ตัวอย่าง + landing page |
| 3 | คุยต่อ + เสนอ pilot | วัดการกลับมาใช้ | ยิง 90 ราย |
| 4 | **ปิดดีลหรือฆ่า** | ตัดสิน | ตัดสิน |

**เวลาต่อสัปดาห์**: ~25 ชม. รวมทั้ง 3 probe · เหลือ ~15 ชม. สำหรับ quick win (ดู `99-quick-wins.md`)

## Gate 2 — ตัดสินหลังสัปดาห์ที่ 4

| ผลลัพธ์ | ทำอะไรต่อ |
|---|---|
| มี 1 probe ผ่าน | ✅ ทุ่มเข้า Phase 3 อันเดียว ฆ่าอีก 2 อันจริง ๆ (ไม่ใช่ "เก็บไว้ก่อน") |
| ผ่าน 2-3 อัน | เลือกอันที่ **money signal แรงที่สุด** ไม่ใช่อันที่สนุกที่สุด |
| ไม่ผ่านเลย | ⛔ **กลับ Phase 1 ไม่ใช่ "ลองอีกหน่อย"** — อ่าน `probe-log.md` หาว่าผิดที่สมมติฐานหรือที่การเข้าถึงลูกค้า แล้วหยิบอันดับ 4-6 จาก scan ขึ้นมา |
| ผ่านแบบก้ำกึ่ง | ยืดได้ **1 สัปดาห์เดียว** แล้วต้องตัด — ความก้ำกึ่งที่ยืดเกิน 1 สัปดาห์คือการปฏิเสธความจริงแบบมีตารางเวลา |

**สิ่งที่ต้องเขียนไม่ว่าผลจะเป็นยังไง**: post-mortem 1 หน้า ต่อ probe — *อะไรที่เดาถูก อะไรที่เดาผิด และเราควรรู้เรื่องนั้นได้เร็วกว่านี้ยังไง*
