# 22 — สแต็กเทคโนโลยี: เก็บ / ตัด / เพิ่ม

> เขียน 2026-10-11 · ประเมินจากลิสต์ที่ Tin ให้มา เทียบกับความต้องการจริงของผลิตภัณฑ์นี้
> ⚠️ รายละเอียดเชิงเทคนิคของบริการภายนอกในไฟล์นี้ติดป้าย `[รอตรวจ]` — **ต้องเปิดเอกสารทางการยืนยันก่อนตัดสิน** เพราะลิมิตและราคาของบริการพวกนี้เปลี่ยนบ่อย

---

## 1. ⭐ ข้อโต้แย้งสองข้อที่ต้องอ่านก่อนเลือกเครื่องมือ

### 1.1 สแต็กที่ให้มาเป็นสแต็กของ R3 ไม่ใช่ R1

**R1 (เส้นบางที่สุด) คือ**: Tin รันสคริปต์บนเครื่องตัวเอง → ออก PDF → ส่งลิงก์/ไฟล์ใน LINE ด้วยมือ

ไม่ต้องมี Supabase · ไม่ต้องมี auth · ไม่ต้องมี Vercel · ไม่ต้องมี RLS · ไม่ต้องมีโดเมน · **ศูนย์ infra**

สแต็กทั้งชุดจำเป็นเมื่อ **ตัวแทนคนอื่นเริ่มใช้เอง** ซึ่งคือ **R3**

> ### ออกแบบสแต็กทั้งหมดล่วงหน้า = ถูกต้อง · สร้างสแต็กทั้งหมดก่อน R3 = เสียเวลาเปล่า

`10-pivot` บันทึกบทเรียนนี้ไว้แล้วด้วยตัวเอง: *"สามรอบที่แล้วผลิตเอกสารเยอะ คุยกับลูกค้าศูนย์ราย อย่าทำซ้ำ"* — **การตั้ง infra ครบก่อนมีลูกค้าคนแรก คือรูปแบบใหม่ของความผิดเดิม**

### 1.2 สแต็กไม่ใช่ความเสี่ยง — มีสามอย่างที่เป็น

| # | ความเสี่ยงจริง | สแต็กช่วยได้ไหม |
|---|---|---|
| 1 | ⛔ **`13` C2 ยังไม่ตอบ: ส่งข้อมูลกรมธรรม์ลูกค้าไปประมวลผลที่ผู้ให้บริการ AI ต่างประเทศได้ไหม** | **ไม่ — และข้อนี้ล้มสแต็กได้ทั้งชุด** |
| 2 | ความแม่นของการอ่านเล่มจริง | ไม่ |
| 3 | มีใครอยากได้ไหม | ไม่ |

→ บรรเทาได้ทางเดียว: **`extract` อยู่หลัง interface ตั้งแต่บรรทัดแรก** เพื่อสลับไปโมเดลที่ประมวลผลในประเทศได้โดยไม่รื้ออะไร

## 2. เก็บ — ตรงกับงานนี้

| เครื่องมือ | ใช้ทำอะไรในงานนี้ | รุ่นที่เริ่มจำเป็น |
|---|---|---|
| **React + Vite + Tailwind** | หน้าจอฝั่งตัวแทน (A1-A8) | R3 |
| **GitHub** | เก็บโค้ด + ชุดเฉลยทดสอบความแม่น | R1 |
| **Vercel** | deploy หน้าเว็บ | R3 |
| **Cloudflare DNS** | โดเมน | R3 |
| **Supabase Postgres** | ฐานข้อมูล · **และ RLS คือหัวใจความปลอดภัย ไม่ใช่ตัวฐานข้อมูล** | R3 |
| **Supabase Storage** | รูป/PDF ดิบ · signed URL อายุสั้น | R3 |
| **Supabase Auth** | ฐานของ session — **แต่ผูกกับ LINE ไม่ใช่ Google** | R3 |
| **PWA** | ⭐ **เพื่อถ่ายออฟไลน์** (R2 ตามที่ตัดสิน) · R3 แค่ติดตั้งลงมือถือได้ | R2 |
| **pg_cron** | ⭐ **ไม่ใช่เตือนความจำ — ใช้ลบรูปดิบตามกำหนด PDPA (CN-5)** + สรุปสัญญาณเตือนให้หัวหน้าหน่วย | R3 |
| **Cloudflare Turnstile** | ⭐ **ไม่ใช่กันบอทตอนล็อกอิน** (LINE Login กันอยู่แล้ว) — ใช้บน **หน้า C5 ที่เป็นลิงก์สาธารณะไม่มี auth** | R3 |
| **Resend** | อีเมล — **ช่องทางสำรอง** หลัง LINE | R4 |

## 3. ตัด — เป็นของโปรเจกต์อื่น หรือไม่มีที่ใช้

| เครื่องมือ | ทำไมตัด |
|---|---|
| **iCal / ซิงค์ Google-Apple Calendar** | **ไม่มีปฏิทินในผลิตภัณฑ์นี้** · ไม่มีการนัดหมาย ไม่มีกำหนดเวลาที่ต้องซิงค์ |
| **Frankfurter API (อัตราแลกเปลี่ยน)** | **บาทเดียว** · กรมธรรม์ไทยไม่มีสกุลเงินอื่น |
| **Web Push** | ตัวแทนยืนอยู่หน้าลูกค้า · ลูกค้าอายุ 70 — **ไม่มีใครในระบบนี้ต้องการการแจ้งเตือนแบบ push** · เลื่อนไป R4+ และน่าจะไม่ทำเลย |
| **Google Login** | ตัวแทนไทยอยู่บน LINE · เพิ่มตัวเลือกล็อกอินที่ไม่มีใครใช้ = เพิ่มพื้นที่ให้บั๊ก |

## 4. LINE — รายละเอียดที่ต้องรู้ก่อนออกแบบ

Tin ตัดสินแล้วว่า **LINE Login + LINE ส่งเอกสาร**

| ประเด็น | สิ่งที่ต้องยืนยัน |
|---|---|
| **LINE Login** | `[รอตรวจ]` Supabase ไม่มี provider LINE ในตัว → ต้องทำผ่าน **custom OIDC** หรือรับ ID token มาตรวจในฟังก์ชันฝั่งเซิร์ฟเวอร์แล้วออก session เอง · **เป็นงาน integration จริง ไม่ใช่กดสวิตช์** — ต้องนับเวลาไว้ |
| ⚠️⚠️ **การส่งถึงลูกค้า** | `[รอตรวจ]` **LINE Messaging API push ข้อความได้เฉพาะผู้ใช้ที่เพิ่ม Official Account เป็นเพื่อนแล้ว** · ลูกค้าอายุ 70 ส่วนใหญ่ไม่ได้เพิ่ม → **ทางหลักที่เป็นจริงคือ "ระบบให้ลิงก์กับตัวแทน แล้วตัวแทนฟอร์เวิร์ดในแชต LINE ของเขาเอง"** (DE-4) · push จาก OA เป็นทางเสริมเท่านั้น (DE-5) |
| **โควตาข้อความ** | `[รอตรวจ]` แพ็กฟรีมีลิมิตจำนวนข้อความต่อเดือน — ถ้าทางหลักคือตัวแทนฟอร์เวิร์ดเอง เรื่องนี้แทบไม่กระทบ |
| **ข้อดีที่ได้ฟรี** | ลูกค้าได้เอกสารในแชตที่เขาคุยกับตัวแทนอยู่แล้ว — **อยู่ในบริบทที่ไว้ใจอยู่แล้ว ไม่ต้องสร้างช่องทางใหม่** |

> 💡 **ผลข้างเคียงที่ดี**: เพราะทางหลักคือตัวแทนฟอร์เวิร์ดลิงก์เอง **R1-R2 ไม่ต้องต่อ LINE API เลย** — Tin ส่งลิงก์ให้ตัวแทนด้วยมือได้ · LINE API เป็นงานของ R3

## 5. เพิ่ม — ช่องโหว่ที่ต้องอุด

| # | สิ่งที่ขาดจากลิสต์ | ทำไมสำคัญ | รุ่น |
|---|---|---|---|
| 1 | ⭐⭐ **ผู้ให้บริการ AI + ไปป์ไลน์การอ่านเอกสาร** | **ข้อตัดสินทางเทคนิคที่ใหญ่ที่สุดของทั้งโปรเจกต์ และไม่มีในลิสต์เลย** · ต้องได้ทั้งฟิลด์**และตำแหน่งที่อ่านมา** (EX-2) · ต้องอยู่หลัง interface เพราะ §1.2 | R1 |
| 2 | ⭐ **คิวงานเบื้องหลัง** | `[รอตรวจ]` **ฟังก์ชันแบบ edge/serverless มีลิมิตเวลารัน — การอ่านเล่มกรมธรรม์หลายสิบหน้าไม่จบในนั้น** · นี่คือกับดักที่คนพลาดบ่อยที่สุดกับสถาปัตยกรรมแบบ Supabase-only · ทางออก: **pgmq** หรือ worker แยกเล็ก ๆ | R3 |
| 3 | **สร้าง PDF ฝั่งเซิร์ฟเวอร์** (headless Chromium) | เอกสารที่ลูกค้าถือต้อง**ย้อนสร้างซ้ำได้เป๊ะ** เพื่อผูกกับบันทึกตรวจสอบ (RE-1) · ไม่ใช่กดปริ้นจากเบราว์เซอร์ซึ่งผลลัพธ์ต่างกันทุกเครื่อง | R1 |
| 4 | ⭐⭐ **ตัวตัดคำไทยสำหรับขึ้นบรรทัดใน PDF** | **ภาษาไทยไม่เว้นวรรคระหว่างคำ** — ตัวเรนเดอร์ PDF ทั่วไปจะตัดบรรทัดกลางคำ ทำให้คนอายุ 70 อ่านไม่ออก · **กับดักที่มองข้ามง่ายที่สุดในสแต็กทั้งชุด และมันทำลายสิ่งที่ Tin ให้ความสำคัญที่สุดพอดี** · ต้องใช้ ICU line-break หรือตัวตัดคำแบบพจนานุกรม | R1 |
| 5 | **ฟอนต์ไทยลิขสิทธิ์เปิด ฝังใน PDF** | Sarabun · IBM Plex Sans Thai · Noto Sans Thai — ต้องฝัง ไม่ใช่อ้างอิง | R1 |
| 6 | ⭐ **ชุดเฉลยทดสอบความแม่น (golden set) + รันอัตโนมัติ** | ไม่มีอันนี้ **การอัปเกรดโมเดลจะทำตัวเลขผิดเงียบ ๆ ต่อหน้าลูกค้า** (EX-7) · เก็บใน GitHub ตั้งแต่ R1 | R1 |
| 7 | ⭐ **RLS policies + เทสต์ RLS** | ความเป็นเจ้าของสามฝ่าย — **ผิดที่นี่คือตัวแทนเห็นลูกค้าของตัวแทนคนอื่น** · ต้องมีเทสต์ ไม่ใช่แค่นโยบาย (ID-5) | R3 |
| 8 | **ตารางบันทึกตรวจสอบแบบเพิ่มได้อย่างเดียวระดับฐานข้อมูล** | revoke UPDATE/DELETE จริง + trigger กัน · ไม่ใช่สัญญาว่าจะไม่แก้ (AU-3) | R3 |
| 9 | ⚠️ **ติดตามข้อผิดพลาด + ล้างข้อมูลส่วนบุคคลออกจาก log** | **payload ของ error ต้องไม่มีข้อมูลกรมธรรม์ลูกค้า** — กับดัก PDPA ที่ซ่อนอยู่ในเครื่องมือ observability ที่ทุกคนติดตั้งโดยไม่คิด | R3 |
| 10 | **เพดานต้นทุน AI ต่อรายงาน** | เล่ม 60 หน้ากินกำไรทั้งรายงาน · ต้องมี cap + ทางลงที่ซื่อสัตย์ (EX-9) | R2 |
| 11 | **แยก dev/staging/prod และห้ามมีข้อมูลลูกค้าจริงนอก prod** | ข้อมูลกรมธรรม์จริงหลุดไปอยู่ใน staging คือเรื่องที่อธิบายกับลูกค้าไม่ได้ | R3 |
| 12 | **สำรองข้อมูล + ส่งออกข้อมูลได้** | สิทธิพาข้อมูลไปตาม PDPA (CN-6) และทางออกถ้าเลิกทำ (`23` D10) | R3 |

## 6. สรุปสแต็กตามรุ่น

```
R0  กระดาษ + ปากกา
      ไม่มีอะไรเลย

R1  เครื่องของ Tin
      สคริปต์ (ภาษาอะไรก็ได้) · interface สำหรับ extract · ผู้ให้บริการ AI หนึ่งราย
      headless Chromium ออก PDF · ตัวตัดคำไทย · ฟอนต์ไทยฝังใน PDF
      guard เป็นโค้ด · audit เป็นไฟล์ append-only · ชุดเฉลยใน GitHub
      ⟵ ไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูล ไม่มีโดเมน

R2  ยังอยู่บนเครื่องตัวเอง + PWA ตัวเล็กสำหรับถ่ายออฟไลน์
      catalog เป็นไฟล์ก่อน ยังไม่ต้องเป็นฐานข้อมูล

R3  ⟵ จุดที่สแต็กทั้งชุดเริ่มจำเป็น
      React+Vite+Tailwind · Vercel · Cloudflare DNS · Turnstile บนหน้า C5
      Supabase Postgres+Storage+Auth · LINE Login (custom OIDC) · RLS + เทสต์
      คิวงาน (pgmq/worker) · pg_cron ลบรูปดิบ · ติดตามข้อผิดพลาดแบบล้าง PII
      LINE Messaging API

R4  billing · Resend · หน้าหัวหน้าหน่วย
```
