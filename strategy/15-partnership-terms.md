# 15 — เช็กลิสต์ข้อตกลงกับหุ้นส่วน Flow's Table

> ⚠️ **นี่ไม่ใช่เอกสารกฎหมาย** เป็นเช็กลิสต์สำหรับ*เปิดบทสนทนา* · เมื่อตกลงกันได้แล้วต้องให้ทนายร่างเป็นสัญญาจริง
> สถานะปัจจุบัน: **มีรายได้อยู่แล้วบางส่วน · คุยกันกว้าง ๆ แต่ไม่มีเอกสาร**

---

## ทำไมต้องทำตอนนี้ และทำไมต้องทำก่อนสร้างอะไร

**มีรายได้แล้ว + ไม่มีเอกสาร = จุดที่หุ้นส่วนพังบ่อยที่สุด** และมันจะแย่ลงพอดีถ้าเริ่มสร้างระบบ เพราะกำลังจะสร้าง**สินทรัพย์ที่กรรมสิทธิ์ไม่ชัด**

> **ตอนนี้คุยง่ายเพราะเงินยังน้อยและยังไม่มีใครเสียเปรียบ — หลังจากนี้จะยากขึ้นทุกเดือน**

**กรอบที่ควรใช้เปิดเรื่อง**: นี่ไม่ใช่การตั้งการ์ดหรือไม่ไว้ใจกัน — เป็นการ**ปกป้องความสัมพันธ์จากเงินที่ยังมาไม่ถึง** เพื่อนที่ทำธุรกิจด้วยกันเสียเพื่อนกันเพราะไม่เคยคุยเรื่องนี้ ไม่ใช่เพราะคุยแล้ว

**ประโยคที่ใช้เปิดได้จริง**:
> *"วงเราเริ่มมีรายได้แล้ว และผมกำลังคิดจะสร้างเครื่องมือมาช่วยงาน อยากเคลียร์เรื่องพวกนี้ตอนที่ยังไม่มีใครเสียเปรียบ — จะได้ไม่ต้องมาคุยตอนที่มันมีเงินก้อนแล้วและคุยยาก"*

## 6 หัวข้อที่ต้องมีคำตอบ

### 1. ความเป็นเจ้าของและรายได้ปัจจุบัน

| คำถาม | คำตอบ |
|---|---|
| ใครเป็นหุ้นส่วน และสัดส่วนเท่าไหร่ | |
| มีนิติบุคคลไหม หรือดำเนินในนามบุคคล | |
| รายได้ปัจจุบันมาจากทางไหนบ้าง แบ่งกันยังไง | |
| ใครลงแรงส่วนไหน — วัดกันยังไง หรือไม่วัด | |
| ค่าใช้จ่ายใครออก | |

### 2. รายได้สายใหม่

| คำถาม | คำตอบ |
|---|---|
| ใครเสนอสายรายได้ใหม่ได้ ใครต้องอนุมัติ | |
| ถ้าคนใดคนหนึ่งนำรายได้ใหม่เข้ามา แบ่งต่างจากเดิมไหม | |
| มีสายไหนที่ตกลงกันว่า**จะไม่ทำ**เลย (เช่น ขายรายชื่อสมาชิก) | |

### 3. กรรมสิทธิ์ในซอฟต์แวร์ ⭐

> หัวข้อที่คนมองข้ามบ่อยที่สุด และเป็นเหตุผลหลักที่เอกสารนี้ต้องมาก่อนการเขียนโค้ด

| คำถาม | คำตอบ |
|---|---|
| ซอฟต์แวร์ที่คนใดคนหนึ่งสร้างด้วยเวลาและเงินตัวเอง เป็นของใคร | |
| ถ้าเป็นของส่วนตัวแล้วให้วงใช้ (license) — เงื่อนไขอะไร ถอนได้ไหม | |
| ถ้าแยกทางกัน ใครเอาซอฟต์แวร์ไป | |
| ถ้าซอฟต์แวร์นั้นถูกเอาไปใช้กับธุรกิจอื่นของผู้สร้าง (เช่น advisory) ได้ไหม | |

### 4. ข้อมูลสมาชิก ⭐

> ผูกกับ PDPA โดยตรง — ดูหมวด E ใน [`13-regulatory-check.md`](13-regulatory-check.md)

| คำถาม | คำตอบ |
|---|---|
| ข้อมูลสมาชิกเป็นของใคร — วง นิติบุคคล หรือคนที่ถือระบบ | |
| ใครเข้าถึงได้บ้าง ระดับไหน | |
| ถ้าแยกทางกัน ข้อมูลไปไหน ใครลบ ใครเก็บ | |
| สมาชิกได้รับแจ้งว่ามีการเก็บข้อมูลอะไรบ้างหรือยัง | |

### 5. Conflict of interest

| คำถาม | คำตอบ |
|---|---|
| สมาชิกกลายเป็นลูกค้า advisory ของหุ้นส่วนคนใดคนหนึ่งได้ไหม | |
| ถ้าได้ ต้องเปิดเผยต่อใคร อย่างไร | |
| หุ้นส่วนรับคอมมิชชั่น/ค่าตอบแทนจากสมาชิกหรือสปอนเซอร์ได้ไหม | |
| ใครตัดสินเมื่อเกิดข้อขัดแย้งเรื่องผลประโยชน์ | |

### 6. ทางออกเมื่อแยกทาง

| คำถาม | คำตอบ |
|---|---|
| ใครเอาชื่อ/แบรนด์ Flow's Table | |
| ความสัมพันธ์กับสมาชิก — ใครติดต่อต่อได้ | |
| มีระยะห้ามทำวงคู่แข่งไหม นานแค่ไหน | |
| ถ้าคนหนึ่งอยากออก อีกคนซื้อคืนได้ไหม ตีมูลค่ายังไง | |

## เกณฑ์ว่าคุยจบแล้ว

- [ ] ทุกหัวข้อมีคำตอบเป็นลายลักษณ์อักษร แม้จะเป็นแค่ *"ยังไม่ตัดสิน จะกลับมาคุยเมื่อ ___"*
- [ ] ข้อ 3 และ 4 ชัดเจนพอที่จะเริ่มเขียนโค้ดได้โดยไม่ต้องเดา
- [ ] ข้อ 4 ไม่ขัดกับข้อกำหนด PDPA (`13` หมวด E)
- [ ] **ข้อตกลงไม่ปิดประตูทาง syndicate ในอนาคต** (`14 §4`) — ระวังข้อ 2 ที่อาจเขียนกว้างเกินจนล็อกตัวเอง
- [ ] ส่งให้ทนายร่างเป็นสัญญาจริง

## ถ้าเจรจาแล้วติดขัด

**อย่าฝืนและอย่าสร้างอะไรที่ผูกกับวง** — แยกเครื่องจำความสัมพันธ์ให้เป็นของ Tin ล้วน ๆ ใช้กับลูกค้า advisory อย่างเดียว แล้วปล่อยให้ Flow's Table เป็นเครดิตและแหล่งแนะนำต่อตามเดิม
ข้อ 8 ของ `14` เขียนเงื่อนไขนี้ไว้แล้ว — **ทางนั้นยังใช้ได้ ไม่ใช่ทางตัน**
