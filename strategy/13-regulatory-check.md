# 13 — เช็กลิสต์กำกับดูแล (ทำสัปดาห์แรก ก่อนสร้างอะไรทั้งสิ้น)

> ⚠️ **ไฟล์นี้คือรายการคำถาม ไม่ใช่คำตอบ** — session ที่สร้างไฟล์นี้ถูกบล็อก egress เปิดเว็บ ก.ล.ต./คปภ. ไม่ได้ **ห้ามใช้ไฟล์นี้เป็นคำตอบทางกฎหมาย** ทุกข้อต้องเปิดแหล่งปฐมภูมิเองและเติมคำตอบพร้อมลิงก์/เลขที่ประกาศ

**ทำไมข้อนี้มาก่อนทุกอย่าง**: ถ้าคำตอบข้อ A1 หรือ B1 เป็น "ไม่ได้" แผนทั้งหมดต้องรื้อ · ต้นทุนการเช็ก = ไม่กี่ชั่วโมง · ต้นทุนการไม่เช็ก = หลายเดือน

---

## A. ขอบเขตของใบอนุญาตที่ถืออยู่

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| A1 | ใบอนุญาตที่ถืออยู่ตอนนี้มีอะไรบ้าง และแต่ละใบให้ทำอะไรได้/ไม่ได้ | | ⬜ |
| A2 | การให้ "คำแนะนำการวางแผนการเงินแบบครบวงจร" (ไม่ใช่แค่แนะนำผลิตภัณฑ์) ต้องมีใบอนุญาตเพิ่มไหม | | ⬜ |
| A3 | คิดค่าธรรมเนียมการวางแผน (fee) แยกจากคอมมิชชั่นได้ไหม ต้องขึ้นทะเบียนอะไรเพิ่ม | | ⬜ |
| A4 | ข้อกำหนดการเปิดเผยค่าตอบแทนต่อลูกค้า — ต้องเปิดเผยอะไร ในรูปแบบไหน | | ⬜ |

## B. การส่งมอบคำแนะนำผ่านซอฟต์แวร์

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| B1 | ⭐ ผู้ถือใบอนุญาต**รายบุคคล**ใช้ซอฟต์แวร์ช่วยผลิตคำแนะนำแล้วตัวเองเซ็นรับรอง ได้แค่ไหน | | ⬜ |
| B2 | เส้นแบ่งระหว่าง "เครื่องมือคำนวณ" (ทำได้เสรี) กับ "การให้คำแนะนำอัตโนมัติ" (ต้องขออนุญาต) อยู่ตรงไหน | | ⬜ |
| B3 | ขอบเขต robo-advisory / บริการวางแผนการลงทุนอัตโนมัติ ต้องขออนุญาตแบบไหน ทุนจดทะเบียนเท่าไหร่ | | ⬜ |
| B4 | ถ้าให้ลูกค้ากรอกข้อมูลเองแล้วระบบออกรายงาน โดยมีคนรีวิวก่อนส่ง — นับเป็นอะไร | | ⬜ |
| B5 | ข้อกำหนดการเก็บหลักฐาน/บันทึกคำแนะนำ (record keeping) นานเท่าไหร่ รูปแบบไหน | | ⬜ |

## C. ข้อมูลส่วนบุคคล (PDPA)

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| C1 | ข้อมูลการเงินลูกค้าเป็นข้อมูลอ่อนไหวไหม ต้องขอความยินยอมแบบไหน | | ⬜ |
| C2 | ส่งข้อมูลลูกค้าไปประมวลผลที่ผู้ให้บริการ AI ต่างประเทศได้ไหม เงื่อนไขอะไร | | ⬜ |
| C3 | ถ้าทำได้ ต้องระบุอะไรในหนังสือยินยอม และต้องมีข้อตกลงประมวลผลข้อมูลกับผู้ให้บริการไหม | | ⬜ |
| C4 | ทางเลือกถ้าส่งออกนอกประเทศไม่ได้ — ประมวลผลในประเทศ / ปกปิดข้อมูลระบุตัวตนก่อนส่ง คุ้มไหม | | ⬜ |

## E. ข้อมูลสมาชิกคอมมูนิตี้ (Flow's Table — ต่างจากข้อมูลลูกค้า advisory)

> สมาชิกไม่ได้เข้ามาในฐานะลูกค้า เขาเข้ามาในฐานะคนในวงที่ไว้ใจกัน **ฐานทางกฎหมายและความคาดหวังจึงต่างกันคนละเรื่อง**

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| E1 | เก็บบันทึกสรุปบทสนทนาของสมาชิกได้ไหม ต้องขอความยินยอมแบบไหน | | ⬜ |
| E2 | ฐานทางกฎหมายที่ใช้ได้คืออะไร — ความยินยอม หรือประโยชน์โดยชอบด้วยกฎหมาย | | ⬜ |
| E3 | ถ้าสมาชิกขอดู/ขอลบข้อมูลของตัวเอง ต้องทำได้ภายในกี่วัน รูปแบบไหน | | ⬜ |
| E4 | ข้อมูลที่สมาชิก **A พูดถึงสมาชิก B** — เก็บได้ไหม ใครเป็นเจ้าของข้อมูลนั้น | | ⬜ |
| E5 | ถ้าแยกทางกับหุ้นส่วน ข้อมูลสมาชิกต้องทำยังไงตามกฎหมาย | | ⬜ |

> ⚠️ ข้อ E4 และ E5 ผูกกับ [`15-partnership-terms.md`](15-partnership-terms.md) ข้อ 4 โดยตรง — **ตอบสองที่ให้ตรงกัน**

## เกณฑ์ตัดสินหลังเช็กเสร็จ

| ผลลัพธ์ | ทำอะไรต่อ |
|---|---|
| B1 = ทำได้ในขอบเขตปัจจุบัน | ✅ เดินหน้าตามแผน |
| B1 = ทำได้แต่ต้องขออนุญาตเพิ่ม | ประเมินต้นทุน/เวลา/ทุนจดทะเบียน — อาจเปลี่ยนลำดับเป็น Phase 2 ก่อน |

| C2 = ส่งออกนอกประเทศไม่ได้ | ต้นทุนสูงขึ้นมาก — ประเมินโมเดลในประเทศหรือปกปิดข้อมูลก่อนส่ง |
