# 13 — เช็กลิสต์กำกับดูแล (ทำสัปดาห์แรก ก่อนสร้างอะไรทั้งสิ้น)

> ⚠️ **ไฟล์นี้คือรายการคำถาม ไม่ใช่คำตอบ** — session ที่สร้างไฟล์นี้ถูกบล็อก egress เปิดเว็บ ก.ล.ต./คปภ. ไม่ได้ **ห้ามใช้ไฟล์นี้เป็นคำตอบทางกฎหมาย** ทุกข้อต้องเปิดแหล่งปฐมภูมิเองและเติมคำตอบพร้อมลิงก์/เลขที่ประกาศ

**ทำไมข้อนี้มาก่อนทุกอย่าง**: ถ้าคำตอบข้อ A1 หรือ B1 เป็น "ไม่ได้" แผนทั้งหมดต้องรื้อ · ต้นทุนการเช็ก = ไม่กี่ชั่วโมง · ต้นทุนการไม่เช็ก = หลายเดือน

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| E1 | เก็บบันทึกสรุปบทสนทนาของสมาชิกได้ไหม ต้องขอความยินยอมแบบไหน | | ⬜ |
| E2 | ฐานทางกฎหมายที่ใช้ได้คืออะไร — ความยินยอม หรือประโยชน์โดยชอบด้วยกฎหมาย | | ⬜ |
| E3 | ถ้าสมาชิกขอดู/ขอลบข้อมูลของตัวเอง ต้องทำได้ภายในกี่วัน รูปแบบไหน | | ⬜ |
| E4 | ข้อมูลที่สมาชิก **A พูดถึงสมาชิก B** — เก็บได้ไหม ใครเป็นเจ้าของข้อมูลนั้น | | ⬜ |
| E5 | ถ้าแยกทางกับหุ้นส่วน ข้อมูลสมาชิกต้องทำยังไงตามกฎหมาย | | ⬜ |

> ⚠️ ข้อ E4 และ E5 ผูกกับ [`15-partnership-terms.md`](15-partnership-terms.md) ข้อ 4 โดยตรง — **ตอบสองที่ให้ตรงกัน**

## F. บริการปกป้องผู้สูงอายุ (wedge ใน `16`)

> ต่างจากหมวด A-B เพราะ**ไม่ใช่คำแนะนำการลงทุน** แต่เป็นการป้องกันและให้ความรู้ — สมมติฐานคือพื้นที่กำกับดูแลน้อยกว่ามาก **ต้องพิสูจน์ ไม่ใช่สมมติ**

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| F1 | ⭐ ให้บริการ "วางระบบป้องกันการฉ้อโกงให้ครอบครัว" โดยคิดค่าบริการ ต้องมีใบอนุญาตอะไรไหม | | ⬜ |
| F2 | เส้นแบ่งระหว่าง "ให้ความรู้เรื่องป้องกันภัย" กับ "ให้คำแนะนำทางการเงิน" อยู่ตรงไหน | | ⬜ |
| F3 | **ผู้ติดต่อที่ไว้ใจได้ (trusted contact)** — ธนาคาร/บลจ. ไทยรองรับการลงทะเบียนแบบนี้ไหม เจ้าไหนบ้าง | | ⬜ |
| F4 | การทบทวนกรมธรรม์/ผู้รับผลประโยชน์ของพ่อแม่ (ชั้น 5) นับเป็นคำแนะนำที่ต้องมีใบอนุญาตไหม | | ⬜ |
| F5 | **PDPA: ข้อมูลของพ่อแม่ ≠ ข้อมูลของลูก** — ต้องได้ความยินยอมจากเจ้าตัวโดยตรงไหม แม้ลูกเป็นคนจ่าย | | ⬜ |
| F6 | ถ้าสงสัยว่าลูกค้ามีภาวะสมองเสื่อม มีหน้าที่ตามกฎหมายต้องทำอะไรไหม (แจ้ง/หยุดธุรกรรม) | | ⬜ |
| F7 | ช่องทางแจ้งเหตุฉ้อโกงของไทยที่ถูกต้อง | ✅ **AOC 1441** (ศูนย์ต่อต้านการฉ้อโกงออนไลน์ รับแจ้ง+ประสานอายัด) · **thaipoliceonline.go.th** (แจ้งความออนไลน์) · เติมใน `templates/family-protocol.md` แล้ว | ✅ |

**สถิติไทยที่ต้องหามาแทนตัวเลขสหรัฐฯ** — ✅ **เสร็จแล้ว 2026-09-20 ได้ 6 ชิ้น เกินเกณฑ์** (ดู `16 §2`)
- [x] ความเสียหายแยกตามช่วงอายุ — **60+ = 8.07% ของเคส แต่ 28.55% ของความเสียหาย**
- [x] สถิติผู้สูงอายุไทยที่ตกเป็นเหยื่อ — 17,895 รายการ · 3,152 ลบ. (8 เดือนแรก 2569)
- [ ] ⚠️ **จำนวนเคสที่ใช้ AI ปลอมเสียงโดยเฉพาะ — ไม่พบ** ทางการไทยเตือนแล้วแต่ยังไม่แยกสถิติ · **ห้ามเดาตัวเลขนี้**

## G. เครื่องมือหน้าลูกค้า (เครื่องอ่านกรมธรรม์ใน `19`-`22`)

> ต่างจากหมวด B เพราะ**เอกสารถูกยื่นให้ลูกค้าของตัวแทนคนอื่น โดยมีชื่อเราอยู่บนนั้น** · สมมติฐานคือการ "สรุปสิ่งที่ลูกค้ามีอยู่แล้ว" ไม่ใช่การให้คำแนะนำ **ต้องพิสูจน์ ไม่ใช่สมมติ**

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| G1 | ⛔⭐ **การสรุปกรมธรรม์ที่ลูกค้ามีอยู่แล้วให้เป็นภาษาเข้าใจง่าย นับเป็น "การให้คำแนะนำ" ที่ต้องมีใบอนุญาตไหม** (ผูกกับ B2) | | ⬜ |
| G2 | ⭐ **การเสนอทดแทน/ยกเลิกกรมธรรม์เดิม มีหน้าที่เปิดเผยข้อมูลอะไรบังคับ มีแบบฟอร์มไหม** — เปิด **ประกาศ คปภ. เรื่องหลักเกณฑ์ วิธีการออก การเสนอขายกรมธรรม์ประกันภัยของบริษัทประกันชีวิต และการปฏิบัติหน้าที่ของตัวแทน/นายหน้า** · บริบท: คปภ. มีหนังสือเตือนตัวแทนเรื่อง "ขายถูกต้อง" ท่ามกลางกระแส **"ปล้นกรมธรรม์"** ลูกค้าเก่า ราว ส.ค. 2569 | | ⬜ |
| G3 | **ร่วมแบรนด์** — เอาชื่อ/โลโก้เราไปอยู่บนเอกสารที่ตัวแทนของบริษัทอื่นยื่นให้ลูกค้า ทำได้ไหม ติดข้อกำหนดบริษัทแม่ไหม | | ⬜ |
| G4 | **PDPA: ข้อมูลกรมธรรม์ของลูกค้า*ของตัวแทน*** — เราเป็นผู้ควบคุมหรือผู้ประมวลผล · ต้องมีข้อตกลงกับตัวแทนไหม · ความยินยอมต้องมาจากเจ้าตัวโดยตรงไหม (ต่างจาก C1-C4 ที่เป็นลูกค้าของเราเอง) | | ⬜ |
| G5 | **ความรับผิดถ้าเครื่องมืออ่านตัวเลขผิดแล้วลูกค้าตัดสินใจจากตัวเลขนั้น** (ผูกกับ D2) | | ⬜ |
| G6 | เก็บบันทึกการใช้งานของตัวแทนคนอื่น (ใครแสดงอะไรให้ลูกค้าไหนดู) ทำได้แค่ไหนตาม PDPA | | ⬜ |

**⛔ G1 · C2 · D3 เป็นตัวบล็อก** — ตอบ "ไม่ได้" ข้อใดข้อหนึ่ง แล้วรูปของผลิตภัณฑ์เปลี่ยน · **ถามก่อนสร้าง ไม่ใช่สร้างก่อนถาม**

## D. ช่องทางตัวแทน (wedge ใน `18`) — ขายให้ / ขายผ่านคนกลางคนอื่น

> ⬆️ **เลื่อนความสำคัญขึ้น 2026-09-20** — เดิมเป็นเรื่อง Phase 2 เดือน 6-12 · ตอนนี้ `18` ทดสอบขนานกับ 8 สัปดาห์แรก **D3 · D4 · D7 ต้องตอบให้ได้ในสัปดาห์ 1-2**

| # | คำถาม | คำตอบ + แหล่ง | สถานะ |
|---|---|---|---|
| D1 | ขายซอฟต์แวร์ให้ผู้ถือใบอนุญาตคนอื่นใช้ — ผู้ขายต้องมีใบอนุญาตไหม | | ⬜ |
| D2 | ความรับผิดตกอยู่กับใครถ้าคำแนะนำที่ระบบผลิตออกมาผิด | | ⬜ |
| D3 | ⭐ มีข้อกำหนดจากบริษัทประกัน/บลจ. ที่ห้ามตัวแทนใช้เครื่องมือ**หรือสคริปต์**ภายนอกไหม | | ⬜ |
| D4 | ⭐ **แบ่งค่าตอบแทนกับผู้ส่งเคสได้แค่ไหน** — ประกาศ คปภ. มีผล **24 ก.ค. 2569** ห้ามผู้**ไม่มี**ใบอนุญาตชักชวน/เปรียบเทียบเพื่อชี้นำ/**รับค่าตอบแทนตามยอดขาย** · ให้ความรู้และแชร์ประสบการณ์ได้ | 🟡 **อ่านจากข่าวรองเท่านั้น** — ต้องเปิดประกาศฉบับจริง เอาเลขที่ประกาศ และดูว่า**ผู้ถือใบอนุญาตด้วยกัน**แบ่งกันได้แค่ไหน | 🟡 |
| D5 | ⭐ **นายหน้าประกันภัยนิติบุคคล** — ทุนจดทะเบียนขั้นต่ำ · คุณสมบัติกรรมการ · ระยะเวลาขออนุญาต · ภาระ compliance ต่อเนื่อง · ต้องมีพนักงานกี่คน | | ⬜ |
| D6 | **สำนักงานตัวแทนประกันภัย** คืออะไร ต่างจาก D5 ยังไง ตั้งได้ยังไง ต้นทุนเท่าไร (มีอยู่ 2,318 แห่ง) | | ⬜ |
| D7 | ⭐ **หลักสูตรอบรมที่เราทำ ขอนับเป็นชั่วโมงต่ออายุใบอนุญาตได้ไหม** — ถ้าได้ มันเกาะไปกับงบที่ถูกบังคับอยู่แล้ว (ต่ออายุ 175,401 รายในปี 2568) | | ⬜ |
| D8 | ขายหลักสูตร/โปรแกรมให้ตัวแทนและหน่วย ต้องขึ้นทะเบียนหรือขออนุญาตอะไรกับ คปภ. ไหม | | ⬜ |

**คำถามที่ต้องถามแหล่งที่เป็นคน ไม่ใช่เอกสาร** (Tin เข้าถึงได้ทั้งสามชั้น — ตัวแทนรายคน · หัวหน้าหน่วย · คนในบริษัทประกัน)
- หัวหน้าหน่วยจ่ายค่าอบรมภายนอกปีละเท่าไร และตัดสินใจเองได้แค่ไหน
- ปีที่แล้วหน่วยซื้ออะไรไปบ้าง — **มีใครขายของแบบนี้อยู่แล้วหรือเปล่า**
